# Wide-field solver v0.11.0 release implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a compact, checksum-verified GitHub v0.11.0 release containing only the v11 runtime, required data, documentation, and a permitted native-colour MMTO example that solves offline.

**Architecture:** Keep the historical repository evidence unchanged and add a separate v11 MMTO demo. Build release archives from a fail-closed allowlist into one temporary directory, validate clean extractions, freeze exact v11 hashes, and publish the verified files under an annotated `v0.11.0` tag.

**Tech Stack:** Python 3.12 standard library (`argparse`, `hashlib`, `json`, `pathlib`, `shutil`, `tarfile`, `tempfile`, `zipfile`), Bash, `uv`, `unittest`, Git, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-09-20-v011-release-design.md`

## Global constraints

- Preserve every frozen legacy, v4, v5, v6, v7, v8, v8a, v9, and v10 byte recorded by its runtime manifest.
- Preserve `examples/milky_way/` and `v11/examples/milky_way/` as historical evidence; do not distribute their unidentified input photograph in v0.11.0 assets.
- Keep all runtime code and data local to this repository; never import from the trail-processing project.
- The MMTO example must not use site/time metadata to seed or tune the stellar astrometric fit.
- Keep all detected sources available, keep large/saturated detections, and keep `withheld_stars == 0`.
- Use the committed v11 `uv.lock` with Python `>=3.12,<3.13`; add no dependency.
- Software remains BSD-3-Clause, copyright © 2026 Peter Andreas Thejll and Chris Flynn.
- Credit the observation as “MMTO all-sky-camera image courtesy of MMT Observatory, provided with permission from Tim Pickering.”
- Build products and clean-extraction directories live under one `mktemp -d` directory and are removed after publication or failure.
- Before every commit, run `uv run --frozen python -m unittest discover -v` and `./demo.sh --output results/check-unique-name` from the repository root.
- Do not relax a numerical regression threshold to hide a failure.

## Review focus

- A missing or substituted MMTO FITS file must fail on its SHA-256 before the solver or packager accepts it; Task 1 tests this in the demo checker and Task 3 tests it in the builder.
- A release archive containing path traversal, an extra file, a cache, a database, or an old-version path must be rejected; Task 3 constructs and rejects such archives.
- A clean extraction with no network access during solving must use only bundled catalogues, ephemerides, and display-name data; Tasks 1 and 5 run the demo with explicit offline arguments.
- Executable bits on `go11.sh`, `go_v0.11.0.sh`, `v11/demo.sh`, and the v11 shell entry points must survive both archive formats; Task 3 inspects modes and Task 5 executes the launchers from both extractions.
- An existing tag, release, or mismatched remote `main` must stop publication rather than overwrite public state; Task 5 performs read-only preflight checks before any GitHub mutation.
